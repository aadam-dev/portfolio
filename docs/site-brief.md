# aadambuilds.dev: site brief (v3)

The single reference for what this site is, who it is for, what it may claim, and how it was decided.
Update it when a decision changes. Older thinking lives in `docs/field-kit-plan.md` (superseded) and `REDESIGN-SPEC.md` (v1).

## 1. What the site is for

Aadam is a studio for product, data and engineering, run by one person who has worked both sides of the table: three years (2023 to 2025) as an analyst in Ghanaian private equity and venture capital, and the engineer who builds and runs the systems businesses operate on. The site has to work for three kinds of guest:

| Guest | What they came to find | Where they should land |
|---|---|---|
| Clients (business owners, operators) | Can this studio build what I need, and has it done it for businesses like mine? | Home → Work in motion → a case study → Start a project |
| Professionals (hiring managers, founders, investors) | Range, depth, judgement, how they think | Home → Work → Lab → About |
| Academics (admissions, supervisors, conference peers) | Education, research, the ICIS paper, grades | About (personal voice, CV, research) |

Goals, in order: make a memorable first moment, prove range with things people can touch, make the next step obvious, and never miss a message.

## 2. Voice

- **First person singular, everywhere.** A personal studio: me and my projects. Home, services, work, the Build desk, the lab and the privacy page all say "I". "We" only ever means you and me ("What are we building?", "Let's build"). "Studio" stays as a brand label, never as a team. Client replicas, testimonials and the PrimeTijara team keep their own voice.
- Plain verbs, sentence case, no filler. Say what something does, not that it is impressive.
- No self-congratulation and no meta-claims ("real items", "actually shipped", "world-class").
- No em-dashes. "Al Boyut" without a hyphen. An-Nur laundry is presented as An-Nur.
- Mirepa Investment Advisors may be named (as on the CV).
- Typography rules from the installed frontend-design skill: no eyebrow above every heading, numbered markers only for real sequences, no middle-dot chains as decoration.

## 8. Back office setup (owner checklist)

Everything degrades gracefully until these are set: forms fall back to WhatsApp, tracking is skipped, `/office` shows what is missing.

1. **Database (Supabase).** Supabase → project → Connect → *Transaction pooler* URI (port 6543). Save it in Vercel → Settings → Environment Variables as `DATABASE_URL` (Preview and Production). If the Supabase Vercel integration is installed it sets `POSTGRES_URL`, which also works.
2. **Tables.** Nothing to run: the site creates any missing tables on first use (`src/db/sql.ts`, idempotent, row level security on every table so Supabase's public keys read nothing). The same SQL is in `supabase/migrations/` for the Supabase GitHub integration; after changing the schema run `npm run db:sql`.
3. **Telegram.** `TELEGRAM_BOT_TOKEN` (from @BotFather; only ever in Vercel, never in the code). Send the bot any message, then in `/office` press **Find my chat** and **Use this chat**, or set `TELEGRAM_CHAT_ID`. The site only sends; it never sets a webhook or polls, so the bot stays free for other jobs.
4. **Office and cron.** `OFFICE_CODE` (the 4-digit first-run sign-in code; change it in Office settings), `SESSION_SECRET` (32+ random characters), `CRON_SECRET` (any long random string; Vercel sends it with the daily digest). Visitor IPs are stored as they are, on the session.
5. **Optional confirmations.** `RESEND_API_KEY` and `INQUIRY_FROM` (after verifying the domain in Resend) email senders a short confirmation. Without them, nothing is emailed.
6. Redeploy, open `/office`, press **Test Telegram**.
7. **Your own devices.** Each one needs a one-time "don't count me" switch, the same `scout-ignore` key the Scout tracker uses, so one step silences both. Any of: sign in to `/office` on that device; open `aadambuilds.dev/?scout-ignore=1` once (handy on a phone; `?scout-ignore=0` undoes it); or run `localStorage.setItem("scout-ignore","1")` in the browser console. `/office` → System → This browser shows the current state.

What reaches Telegram (every update opens with "🌐 aadambuilds.dev" and ends with `#site` plus a tag):
- **👋 New visit** `#visit`, silent: place, device, where they came from, landing page. At most 30 an hour; the rest are only counted and noted in the digest.
- **🔔 Notable visit** `#notable`, with sound, as a reply under that visit's line: returned, stayed 60s+, opened a case study, or played with the desk or Lab; once per visit, with pages and what they did.
- **📩 Message / Build brief / Hire brief** `#message`: name, contact, budget, the message, the brief link and the visit behind it; buttons to the inbox, the brief and WhatsApp when the contact is a phone number.
- **📊 Daily digest** `#digest` at 08:00 Accra (`vercel.json`).

Tracking only runs on Vercel deployments and respects Do Not Track and Global Privacy Control. `/privacy` explains it to visitors.

## 9. Performance budget

- Below the hero: at 4× CPU throttle, under 3% of frames over 33 ms and no long task over 100 ms during scroll (v2 harness).
- Hero: a rendered image (no WebGL), LCP plate under 400 KB; the only live part is the register on the monitor, mounted when the browser is idle.
- 3D and map code load after first paint and never block it.
